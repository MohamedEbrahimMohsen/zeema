Questions developers ask

How is this different from Mermaid, PlantUML, or Structurizr?

Diagram-as-code tools describe a picture: boxes, arrows, layout. Zeema describes the system itself. Every node is a catalogue component with a kind, edges carry a contract (protocol, mode, timeout, retry policy, idempotency), and rules check the design. Diagrams are one view of the data: the canvas draws it, and zeema render exports SVG or Mermaid.

Is it free?

Yes. The schema, the engine and the CLI are open source, and the canvas is free to use.

Do I need an account?

Not to explore. Public designs open read-only. Sign in with GitHub when you want to create a design, or clone one and keep your edits.

Where does my design live?

On Zeema, public or private. A new design starts private; clone a public one to start from it, and publish a release when it is ready. It is also yours as files: export a zip with the YAML and its layout, commit it next to your code, run zeema lint in CI, and import it back whenever you like.

Which AI agents can use it?

Any agent that can read a file. A design is plain YAML with a JSON Schema, and llms.txt indexes every kind, component and rule as pages an agent can fetch. Coding agents load the design as context, check their work against it, and propose changes as diffs.

Is it tied to one cloud?

No. The catalogue covers AWS, Azure, Google Cloud, Cloudflare, Kubernetes, Oracle Cloud, IBM Cloud, Alibaba Cloud, DigitalOcean, OpenStack and Outscale, plus vendor-neutral products such as Kafka and Redis. Each component maps to a kind like worker or object-store, so a design means the same thing whichever vendor you pick.

## Candidate kinds that look like duplicates

- **coordination-service / control-plane-coordinator / sharding-coordinator**: all hold cluster metadata or assign ownership; likely one kind coordination-service with a role property
- **stream / event-store / sequencer**: append-only ordered logs; event-store and sequencer are stream-as-system-of-record roles
- **queue roles (dlq, retry, offline-mailbox, frontier)**: one queue kind with a role enum
- **ledger / sql-database appendOnly / event-store**: ledger is an append-only double-entry store; keep as kind, note overlap
- **worker / etl-job / scheduled-job**: background work; distinguish by trigger (queue, schedule, batch)
- **realtime-gateway / notification-service**: realtime-gateway holds connections; notification-service fans out to providers
- **search-index / geospatial-index**: geospatial-index may be search-index with structure geo
- **identity-provider / key-management / authorization**: security boundary services; one category
- **mail-store / stateful app-server / matching-engine**: stateful single-writer servers; may be app-server with stateful true and a role
- **web-client / mobile-client / desktop-client / sdk-client**: one client kind with platform enum is enough for rules
- **data-warehouse / timeseries-database / graph-database / nosql-database**: specialised stores; keep separate only where a rule needs it
